# Frontend route map

Route paths, per-route access, and the Convex query/mutation shape each route calls, for the Vite+React SPA (ADR-0003) rendering the schema in [`convex/schema.ts`](../../convex/schema.ts). Originated as a pre-build design artifact (wayfinder ticket [#6](https://github.com/hugoforte/ChoirManagement/issues/6)); now describes the shipped `src/routes/` tree, kept current as routes and their access rules change (most recently by #83's Share Link route).

**Updated after #7 resolved**: public routes live under a distinct `/public/...` prefix and call only dedicated `convex/public.ts` functions that never touch `rsvps` or `members` — not a conditional branch inside the authenticated routes. `/` and `/events` below are now member-only; the public surface is `/public/events` and `/public/events/:eventId`.

## Legend

- **Access**: `public` (no login required), `member` (any authenticated Member, any Role), `director+` (Role = admin or director), `admin` (Role = admin only). Each of these corresponds to a named Capability in `convex/lib/capabilities.ts`, read by both `requireCan` (backend) and `can` (frontend) — see CONTEXT.md's Capability entry.
- **Convex calls**: named by table + shape, matching the shipped `convex/*.ts` function names where one exists.

## Notes on Role gating

Per CONTEXT.md: **Admin** manages Members/Roles/choir settings; **Director** manages Music Library, Member roster, and Events; **Chorister** views the Music Library and RSVPs. `convex/lib/capabilities.ts` names eight Capabilities from that prose — `manageEvents`, `manageLibrary`, `manageRoster`, `manageBulletins`, `deletePublishedBulletins`, `managePolls`, `assignRoles`, `manageSettings` — with `requireCan` (backend) and `can` (frontend) both reading the same table, so a route's gate and its backing mutation's check can't drift apart the way two independent Role-list literals could.

`manageBulletins` and `managePolls` (#79) resolve to the same `admin`/`director` pair as `manageEvents` does today, and are still separate Capabilities. A future chorister-secretary should be able to write Bulletins or run a Poll without also gaining the ability to edit Events; two rules that happen to agree are cheap to keep apart now and expensive to pull apart later.

The token Share Link route (`/s/:token`, ADR-0004) is the app's only unauthenticated read of Member-only content. Its access column reads two ways deliberately: the mode on the Bulletin's Share Link, not the visitor, decides whether an account is required. The unauthenticated half is served only by `convex/public.ts`, which never queries `members` or `rsvps`, and returns a hand-listed projection rather than the stored document — so a field added to `bulletins` or `events` later cannot leak through it. Polls get no such route at any point: a Poll's grid is named personal data about identifiable Members, and nothing justified handing it to whoever holds a URL.

## Open questions / assumptions flagged for the human

1. ~~**Member roster page scope for non-Admin Directors.**~~ Resolved by #28: Directors reach `/members/manage` (`manageRoster`) and see the roster, but the Role control is Admin-only (`assignRoles`) — rendered as plain text for a Director, an editable `<select>` for an Admin. No separate Director-only roster action exists yet (no invite/remove-Member flow in v1); flag that separately if wanted.
2. **Piece file preview vs. download only.** Assumed the Piece detail view renders inline preview where the browser can (e.g. PDF in an `<iframe>`/object viewer, audio in an `<audio>` tag) and falls back to a plain download link for other `kind`s (`musescore`, `midi`) — no player/renderer is being built per issue #1's out-of-scope list, so "preview" here means "whatever the browser does natively with the file type," not custom UI.
3. **No standalone `/pieces/:id/edit` split from `/library/manage`.** Assumed Piece editing happens via a modal/inline form on `/library/manage` rather than a dedicated edit route per Piece (unlike Events, which got a dedicated `/events/manage/:eventId` because the Setlist builder is more complex). Flag if a dedicated Piece edit route is wanted for consistency.
